# Zumbra 0.14.3 — native method hot-loop performance fix

This patch keeps the public language version at 0.14.3 and changes only the C11 native backend.

The native generator now emits direct calls for synchronous struct methods when the method value is used only as the immediate call target. Dynamic receiver calls can also bypass bound-method materialization when all candidate methods are synchronous. Async methods continue to use the normal `z_call` path so task semantics remain intact.

This is required by long-running low-level code such as the Z23 NES CPU/PPU loop, where materializing a bound method for every `cpu.step()`, `self.read()`, `self.setFlag()` and similar call can allocate without bound and eventually freeze or kill the desktop process.

Validation performed in the artifact environment:

```bash
go test ./nativec -run 'TestZ9AsyncMethodBuildsAndRunsNatively|TestNativeUnknownLiteralsInsideDynamicLoopPreserveSourceKinds|TestZ11HTTPAPIBuildsAndRunsNatively|TestZ11WebSocketBuildsAndRunsNatively'
```

Full `go test ./...` could not complete in the artifact environment because external Go modules could not be downloaded. Run it in the local Debian checkout before installing the rebuilt `zumbra`.
