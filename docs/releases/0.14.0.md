# Zumbra 0.14.0

**Marco:** Z18 — tooling oficial e fechamento da linguagem.

A 0.14.0 entrega a Z18 integralmente, sem releases intermediárias Z18.1 ou Z18.2.

## Adicionado

- `zumbra fmt` com descoberta recursiva, modo de escrita, `--check`, `--stdout`, indentação configurável, preservação de comentários, validação e idempotência.
- `zumbra lint` com diagnósticos textuais ou JSON, regras textuais/AST, pipeline semântico e `--deny-warnings`.
- `zumbra doc` com saída Markdown/JSON e extração de funções, constantes, structs, enums, aliases e FFI.
- `zumbra project` com `init`, `info`, `check`, `test`, `run`, `build`, `fmt`, `lint`, `doc` e `clean`.
- `zumbra profile` com estatísticas, tempos por estágio, alocações e perfis CPU/heap compatíveis com `pprof`.
- `zumbra lsp --stdio` com diagnósticos, formatter, completion, hover e document symbols.
- extensão oficial VS Code em `editors/vscode`.
- pacote compartilhado `diagnostics` com códigos, severidade e intervalos estáveis.
- tempos de parser, módulos, semântica, tipos, HIR, MIR e otimização em `pipeline.Result`.
- gate `scripts/test-z18-tooling.sh`.

## Alterado

- versão da CLI atualizada de `0.13.0` para `0.14.0`.
- `zumbra check` agora aceita `--json` e retorna falha real quando existem erros.
- mensagens do pipeline passam a carregar arquivo, código e posição estruturada.
- README e referência de sintaxe documentam o fluxo completo da Z18.
- todos os comandos de tooling tratam `--help` como sucesso e encerram com código `0`.
- a verificação de higiene aceita artefatos locais corretamente ignorados pelo Git e continua rejeitando artefatos rastreados ou candidatos a commit.

## Compatibilidade

- nenhum recurso de linguagem da Z17 foi removido;
- programas `.zum` existentes continuam válidos;
- `pipeline.Diagnostic` ganhou campos, preservando os campos antigos `Stage`, `Message` e `Warning`;
- projetos desktop existentes com `[app]` continuam compatíveis;
- o formatter é opt-in e não altera arquivos sem o comando explícito.
