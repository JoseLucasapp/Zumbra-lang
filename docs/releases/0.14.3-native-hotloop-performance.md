# Zumbra 0.14.3 native hot-loop performance patch

This patch keeps the public compiler version at `0.14.3` and improves the C11 backend used by desktop/game workloads.

## Native backend changes

- emits direct calls for statically known functions and struct methods;
- avoids bound-method allocation when a method value is only used as a call callee;
- emits direct struct-field slot access for typed struct values;
- specializes array/buffer positional indexing;
- specializes constant string dictionary keys;
- emits static string literals for native C constants;
- adds inline numeric, boolean and conversion helpers to generated C;
- adds faster dictionary lookup paths for generated constant-key accesses.

## Why this exists

The NES emulator runs millions of integer, byte-array, dictionary and struct-field operations per second. The portable dynamic C runtime is correct, but too expensive for this workload when every CPU/PPU/APU tick goes through generic dispatch. This patch preserves the public Zumbra version while lowering hot native paths directly to C helpers.

## Validation

Run:

```bash
go test ./...
go build -o build/zumbra .
./build/zumbra --version
```

Expected version:

```text
0.14.3
```

Then build a native project and inspect `build/native/.../main.c` for generated helpers such as `z_gen_binary_op`, `z_gen_index_at` and `z_get_struct_field_at`.
