# Zumbra 0.14.5 — static string literals for native hot loops

Zumbra 0.14.5 is a native-backend performance stabilization release for long-running desktop and emulator workloads.

## Main change

The C backend now emits string literals as `z_string_static("...")` instead of allocating a fresh heap string with `z_string("...")` for every literal evaluation.

This removes a major source of allocation churn in hot loops that repeatedly access dictionary keys, module labels, status strings, and other immutable literals. Dynamic strings still use the normal owned-string path.

## Compatibility

The language version is bumped to `0.14.5`. The runtime ABI keeps `z_string()` for dynamic/owned strings and `z_string_static()` for immutable literals.

## Validation intent

Projects with sustained loops should check generated C for `z_string_static` in literal-heavy paths and verify that active memory remains stable across hundreds of frames.
