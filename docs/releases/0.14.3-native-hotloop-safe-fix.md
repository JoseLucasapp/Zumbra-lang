# Zumbra 0.14.3 native hot-loop safe fix

This hotfix keeps the public compiler version at `0.14.3` and fixes the unsafe native hot-loop patch.

## Fixed

- Removed unsafe direct `zf_*` calls from generated C. Calls now go through `z_call`, preserving async task wrapping, bound methods, and recursive/native runtime semantics.
- Restored string literal emission as `z_string(...)`, preserving the existing native generator contract checked by `TestNativeUnknownLiteralsInsideDynamicLoopPreserveSourceKinds`.
- Restored method field lookup when the field result is used as a callable. The unsafe placeholder `z_null()` path is disabled.
- Kept safe hot-loop runtime helpers for numeric operations, indexed array/buffer access, cached dictionary string lookup, and runtime support additions.

## Validation target

Run:

```bash
gofmt -w nativec/generator.go
go test ./...
go build -o build/zumbra .
./build/zumbra --version
```

Expected version remains:

```text
0.14.3
```
